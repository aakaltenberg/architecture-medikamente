# Задание 3. Оценка Data Encryption at Rest and In Transit

## 1. Классификация данных

Данные классифицируются по **чувствительности**, **состоянию** (хранение / передача) и **профилю риска**. Выделены четыре уровня чувствительности:

| Уровень | Категория | Примеры данных | Профиль риска |
|---------|-----------|----------------|----------------|
| **0** | Публичные | Общая информация о клинике, прайс-листы | Низкий |
| **1** | Внутренние | Внутренние регламенты, расписание врачей (без ФИО пациентов) | Низкий / Средний |
| **2** | Конфиденциальные | Персональные данные пациентов (ФИО, телефон, email, адрес), финансовые данные (суммы, реквизиты), договоры | Высокий |
| **3** | Строго конфиденциальные | Медицинские карты, диагнозы, результаты анализов, биометрические данные, платёжные реквизиты (полные) | Критический |

**Состояния данных:**
- **At Rest** — данные в хранилищах: БД PostgreSQL, объектное хранилище MinIO/S3, файловые системы серверов, резервные копии, архивы.
- **In Transit** — данные, передаваемые по сети: между клиентами (порталы) и серверами, между микросервисами, между системами (CRM, 1С, лаборатория), между ЦОД и филиалами.

## 2. Обоснование необходимости защиты

| Уровень | Почему нужна защита |
|---------|----------------------|
| **0** | Защита не требуется, но целостность и доступность важны. |
| **1** | Необходима защита от несанкционированного изменения и раскрытия внутренней информации, которая может нанести ограниченный ущерб. |
| **2** | Обязательна в соответствии с 152-ФЗ («О персональных данных»), 323-ФЗ («Об основах охраны здоровья»). Раскрытие приведёт к репутационному и финансовому ущербу. |
| **3** | Критическая защита: утечка может нанести тяжкий вред здоровью, жизни, привести к судебным искам, потере доверия. Требуется соответствие PCI DSS (для платёжных данных) и отраслевым стандартам. |

## 3. Сводная классификация

| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|----------------------------|---------------------|
| Публичные (прайс-листы, информация о клинике) | Обеспечение целостности и доступности | Шифрование дисков, HTTPS |
| Внутренние (регламенты, расписание без ПДн) | Защита от несанкционированного изменения и раскрытия | Шифрование дисков, VPN, TLS |
| Персональные данные (ФИО, контакты, адреса) | Соответствие 152-ФЗ, 323-ФЗ, предотвращение утечек | TLS, TDE в PostgreSQL, шифрование столбцов (pgcrypto), DLP |
| Финансовые данные (суммы, реквизиты) | Защита от мошенничества, соответствие PCI DSS | Токенизация, шифрование БД, mTLS, аудит |
| Медицинские данные (диагнозы, анализы, биометрия) | Критическая защита врачебной тайны | Envelope encryption, HSM, KMS (Vault), mTLS, строгий RBAC/ABAC, аудит |

## 4. Инструменты защиты данных

### 4.1. Шифрование при хранении (At Rest)

| Уровень | Методы и инструменты |
|---------|-----------------------|
| **0–1** | Полное шифрование дисков (LUKS, BitLocker). |
| **2** | - Шифрование на уровне СУБД: TDE (Transparent Data Encryption) в PostgreSQL или файловой системы.
<br>- Шифрование отдельных столбцов с помощью pgcrypto (AES-256).
<br>- Для объектного хранилища MinIO: автоматическое шифрование на уровне bucket (SSE-S3, SSE-C). |
| **3** | - Шифрование на уровне приложения с использованием конверт-шифрования (envelope encryption).
<br>- Управление ключами через KMS (Hashicorp Vault, AWS KMS) с разделением ролей.
<br>- Аппаратные модули HSM для хранения мастер-ключей.
<br>- Резервные копии также шифруются (Veeam с шифрованием, Bacula с GPG). |

**Общие меры:**
- Все ключи хранятся отдельно от данных (в Vault/HSM).
- Ротация ключей не реже одного раза в год (или при подозрении компрометации).
- Шифрование применяется ко всем носителям, включая тестовые и dev-среды.

### 4.2. Шифрование при передаче (In Transit)

| Уровень | Методы и инструменты |
|---------|-----------------------|
| **0–1** | HTTPS/TLS 1.3 для веб-трафика; SSH для администрирования; VPN (WireGuard/IPsec) для удалённого доступа. |
| **2–3** | - Взаимный TLS (mTLS) для межсервисного взаимодействия и интеграции с лабораторией.
<br>- API Gateway с обязательным TLS и проверкой сертификатов.
<br>- Шифрование электронной почты (S/MIME, PGP) при отправке чувствительной информации.
<br>- Для передачи в 1С и ККМ — защищённые протоколы (TLS, OLE через VPN).
<br>- Использование выделенных VLAN и микросегментации сети. |

**Общие меры:**
- Запрет использования нешифрованных протоколов (HTTP, FTP, Telnet) в целевой архитектуре.
- Политика HSTS для веб-порталов.
- Регулярное обновление TLS-сертификатов, использование доверенного удостоверяющего центра.

### 4.3. Управление ключами и сертификатами

| Инструмент | Назначение |
|------------|------------|
| **Hashicorp Vault** | Централизованное хранение секретов, динамическая генерация ключей, ротация, аудит. |
| **HSM (аппаратный модуль)** | Хранение мастер-ключей, выполнение криптоопераций, защита от физического извлечения. |
| **PKI** | Управление сертификатами X.509 для TLS/mTLS, автоматическая выдача через ACME (Let's Encrypt или внутренний CA). |

### 4.4. Контроль доступа и аудит

| Инструмент | Назначение |
|------------|------------|
| **IAM (Keycloak)** | Аутентификация, RBAC/ABAC, MFA для всех систем. |
| **SIEM (ELK/Wazuh)** | Сбор и анализ логов доступа, выявление аномалий. |
| **DLP** | Мониторинг и блокировка попыток передачи конфиденциальных данных за пределы периметра. |
| **Data Classification** | Автоматическое тегирование данных, применение политик шифрования на основе тегов. |

## 5. Реестр программных и аппаратных средств защиты

| № | Средство | Тип | Назначение | Область применения |
|---|----------|-----|------------|---------------------|
| 1 | Hashicorp Vault | Программное | Управление секретами и ключами шифрования | Все уровни (2–3) |

| 9 | WireGuard / IPsec VPN | Программное / аппаратное | Шифрование каналов между офисами и удалёнными пользователями | Все уровни |
| 10 | Keycloak | Программное | IAM, MFA | Все уровни |

| 14 | Промышленные межсетевые экраны (NGFW) | Аппаратное / ПО | Контроль трафика, фильтрация, VPN | Периметр сети |
| 15 | Аппаратные HSM (например, Thales, Utimaco) | Аппаратное | Криптографическая защита ключей | Уровень 3 |

## 6. Заключение

Предложенная стратегия покрывает все состояния данных (at rest, in transit), обеспечивает соответствие требованиям законодательства РФ и отраслевым стандартам. Внедрение описанных инструментов позволит:
- Гарантировать конфиденциальность и целостность данных.
- Обеспечить масштабируемость и управляемость систем шифрования.
- Снизить риски утечек и несанкционированного доступа.
